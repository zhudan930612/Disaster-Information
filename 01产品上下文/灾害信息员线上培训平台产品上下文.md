## 产品定位

**系统名称**：灾害信息员线上学习管理平台（材料中亦出现“灾害信息员学习平台”表述）

**核心定位**：面向各级灾害信息员，提供“学习-练习-考试-竞赛”一体化的线上培训与能力评估平台。

**治理/运营模式**：
- 国家级、省市县级分层运营与分级权限管理。
- 管理端负责内容与赛务配置，移动端承担学习与参赛执行。
- 学员基于上报到应急部的灾害信息员数据，通过移动应急APP进入平台H5并完成登录使用。

**目标用户**：
- **灾害信息员（学员）**：在移动端进行课程学习、练习、考试、竞赛、查看学习成果。
- **省/市/县管理员**：负责辖区考试与培训组织、用户管理、学员数据查看。
- **国家级管理员**：负责全国范围规则配置、资源管理、系统级治理与统计。

**核心场景**：
- **日常学习培训**：按课程分类学习，累计学习时长与学习记录。
- **阶段性考核与竞赛**：按练习赛、初赛、复赛、决赛进行组织和参与。
- **监管统计与复盘**：按赛事、区域、角色进行结果统计与数据导出。

## 商业模式

**商业模式定位**：
- **公司定位**：待补充（材料未明确厂商商业信息）。
- **核心业务**：为应急/减灾条线提供培训与竞赛数字化平台能力。
- **核心客户**：政府与事业单位管理部门（国家-省-市-县体系）。
- **业务聚焦**：组织管理效率、培训执行标准化、数据可追踪。

**收费模式**：
- 项目制收费，以平台建设费用为主。
- 后续运维服务费用：每年40万元（合同细则按项目合同执行）。

**核心价值主张**：
- **对管理部门**：统一规则配置、统一过程监管、统一结果归集。
- **对管理员**：减少线下组织成本，提升考试竞赛执行效率。
- **对灾害信息员**：随时随地学习与参赛，能力成长可量化。

**战略原则**：以“可组织、可考核、可追踪、可复盘”为核心主线。

**核心竞争力与商业壁垒**：
- **壁垒本质**：分级组织能力+赛训一体化流程+持续沉淀的数据资产。
- **价值闭环**：
  - 对管理部门：过程管控+结果统计。
  - 对学员：学习提升+竞赛激励。
- **竞争力构建路径**：
  - **组织流程数字化能力**（短期）：快速落地各级赛事与培训。
  - **数据与内容资产能力**（长期）：题库、课程、行为数据持续沉淀。

**风险规避策略**：
- 分级权限隔离，降低跨层级误操作风险。
- 关键过程留痕（操作日志/异常日志），支撑审计与回溯。

**对功能设计的影响**：
- 功能必须先满足“分级治理”和“流程可追踪”。
- 所有关键模块应支持统计与导出能力。

## 术语表

| 术语 | 定义 | 易混淆概念 |
|------|------|------------|
| 初赛 | 竞赛第一阶段，线上排名赛制，取多次最优成绩排名，前40%晋级 | 不等同于练习赛，初赛成绩决定晋级 |
| 复赛 | 竞赛第二阶段，线上为积分赛制（5天5轮），省级团体为现场分组循环赛 | 个人复赛为线上异步比赛，无需等待对手同时在线 |
| 决赛 | 竞赛第三阶段，线上为淘汰赛制（3天3轮），省级团体为现场淘汰赛 | 每轮淘汰1/2，奖项与淘汰轮次绑定 |
| 排名赛制 | 取多次答题最优成绩进行排名的赛制（初赛） | 不等同于积分赛制，不累积 |
| 积分赛制 | 每轮比赛按胜负累计积分，多轮后按总积分排名（复赛） | 不等同于淘汰赛，可输多场仍晋级 |
| 淘汰赛制 | 每轮比赛胜者晋级败者淘汰的赛制（决赛） | 不等同于积分赛，输一场即淘汰 |
| 异步比赛 | 匹配对手后双方可在规定时段内各自完成答题，无需同时在线 | 不等同于实时对战，匹配后独立完成 |
| 线上考试 | 管理员发布的标准化考试任务 | 与”竞赛”不同，考试无晋级与对抗属性 |
| 题库 | 题目集合及其分类、权限、分值、时限配置载体 | 与课程资源不同，题库用于答题测评 |
| 学习证书 | 完成指定课程后在移动端可查看/保存的成果凭证 | 不等同于竞赛成绩 |
| 分级管理员 | 国家级与省市县级等不同权限层级管理员 | 不等同于普通学员账号 |
| 无痕跳转 | 用户在一个已登录系统中直接进入另一个系统，无需重复登录 | 不等同于普通页面跳转 |
| 组织奖 | 对各级应急管理部门组织参赛工作的评定奖励 | 按4项指标加权计分排名，非比赛成绩直接决定 |
| 轮空 | 参赛人数为奇数时，系统自动判一人/一队获胜晋级 | 不等同于获胜，不产生比赛数据 |
| 灾害信息员数据库 | 全国灾害信息员登记备案的权威用户数据源 | 不等同于平台自有用户表，为外部数据源 |

## 模块清单

### 移动端学习中心（✅ 已上线）
**定位**：面向学员的一站式学习与参赛入口。  
**核心场景**：学习课程、参加考试、参与竞赛、查看成果。  
**使用角色**：灾害信息员（学习、练习、答题、查证书）。  
**主要流程**：
```
登录 → 首页金刚区选择功能 → 学习/练习/考试/竞赛 → 结果沉淀到“学习/我的”
```
**与其他模块的关系**：
- → 课程与资源管理：读取课程内容。
- → 考试管理：接收考试任务。
- → 竞赛管理：接收赛程任务与规则。
- ← 用户与组织管理：获得身份与组织归属。

### 考试与题库管理（✅ 已上线）
**定位**：提供题目资产管理与考试发布执行能力。  
**核心场景**：题库建设、题目维护、考试任务发布、考试统计。  
**使用角色**：国家级管理员、省市县管理员（按权限）。  
**主要流程**：
```
新建题库 → 维护题目（单选/多选/判断）→ 发布考试 → 学员作答 → 统计与导出
```
**与其他模块的关系**：
- → 移动端学习中心：下发考试任务。
- → 数据统计模块：提供考试结果数据。

### 业务竞赛管理（✅ 已上线）
**定位**：提供赛事全流程配置、执行与结果管理能力。  
**核心场景**：国家级/省级赛事组织，多阶段赛程管理，个人赛+团体赛双赛道并行。  
**使用角色**：国家级管理员、省市县管理员、灾害信息员。  
**赛事阶段**：
- **初赛**（线上·排名赛制）：8.25-8.29，取最优成绩排名，前40%晋级
- **复赛**（线上·积分赛制+省级现场赛）：9.1-9.11，5天5轮积分赛，前25%晋级
- **决赛**（线上·淘汰赛制+省级现场赛）：9.15-9.25，3天3轮淘汰赛
**赛道**：
- **个人赛**：村级/乡级/县级/市级/省级四级，灾害信息员以个人名义参赛
- **团体赛**：县级（3人）/市级（4人）/省级（5人）三级，按层级组成参赛队
**主要流程**：
```
创建竞赛 → 配置阶段（初赛/复赛/决赛）→ 配置赛道（个人/团体）→ 报名组织 → 学员参赛 → 自动匹配对手 → 排名/积分/淘汰判定 → 晋级 → 奖项评定
```
**与其他模块的关系**：
- ← 题库管理：引用题库作为赛题来源。
- → 报名入口/人员详情：承接参赛组织与人员数据。
- → 竞赛结果/统计导出：输出结果数据。
- → 奖项管理：自动评定团体奖/个人奖/组织奖。

**关键业务规则**（来源于《全国灾害信息员业务技能大赛竞赛规则》）：
- 答题规则：每次20题，每题5分，90秒限时，不可暂停/返回上一题
- 异步比赛：匹配对手后各自独立答题，无需等待同时在线
- 初赛每人最多3次答题，取最优成绩；复赛5天5轮积分赛；决赛3天3轮淘汰赛
- 同级别一对一匹配（省级对省级、市级对市级...），团体队员按层级对应
- 排名优先级：分数 > 用时；复赛累计积分 > 平均答对题数 > 平均用时
- 特殊地区规则：无县级行政区/直辖市/兵团有独立组队和排名规则

### 报名与人员管理（✅ 已上线）
**定位**：承接竞赛报名组织与参赛人员信息管理。  
**核心场景**：分级单位报名、人员检索、参赛状态查看。  
**使用角色**：各级管理员。  
**主要流程**：
```
选择赛事与层级 → 组织报名 → 查询人员详情 → 导出名单/数据
```
**与其他模块的关系**：
- ← 机构管理：获取组织树与层级。
- → 竞赛执行与结果模块：提供参赛主体数据。

### 数据统计与导出（✅ 已上线）
**定位**：提供监管指标、过程分析与结果导出能力。  
**核心场景**：看板查看、按条件筛选、导出业务数据。  
**使用角色**：各级管理员、运营复盘角色。  
**主要流程**：
```
选择赛事/阶段/区域/时间 → 查看统计 → 导出数据
```
**与其他模块的关系**：
- ← 考试管理/竞赛管理/用户行为：汇总多来源数据。

### 系统管理（✅ 已上线）
**定位**：保障平台基础治理、权限、安全与可运维。  
**核心场景**：账号/角色/机构/日志/协议管理，人员批量导入。  
**使用角色**：国家级管理员、系统运维角色。  
**主要流程**：
```
配置组织与账号角色 → 分配权限 → 运行留痕（操作/异常日志）→ 持续维护
```
**与其他模块的关系**：
- → 全模块：提供权限、组织、审计底座能力。

### 商城与激励（✅ 已上线）
**定位**：承接学习积分与激励兑换相关能力。  
**核心场景**：商品分类、商品管理、专题、交易记录。  
**使用角色**：管理员、学员（前台兑换场景待补充）。  
**主要流程**：积分获取 → 积分兑换（功能已开发）。

## 数据底座

平台当前可识别的核心数据域如下：

### 用户与组织信息库
**定位**：承接用户身份、组织归属、层级结构。  
**核心内容**：
- 用户基础信息（姓名、手机号、身份等级、来源渠道等）。
- 用户等级体系（国家、省、市、县、乡、村）。
- 组织结构（国家/省/市/县/乡/村机构树）。
- 角色与权限映射（账号、角色、权限关系）。

### 课程与内容资源库
**定位**：承载学习资源及分类体系。  
**核心内容**：
- 课程基础信息（课程名称、分类、时长）。
- 内容分类（已确认9大类）。
- 讲师/专题/政策专栏内容（部分字段待补充）。

### 题库与测评数据
**定位**：支撑练习、考试、竞赛答题。  
**核心内容**：
- 题库信息、题目结构、分值、时限、主题分类、权限范围。
- 作答记录、成绩、答题时长、最高分等结果数据。

### 赛事与报名数据
**定位**：支撑赛程组织与结果判定。  
**核心内容**：
- 赛事主数据（赛程阶段、时间、规则、关联题库）。
- 报名数据（个人/团体、单位、层级、区划节点）。
- 结果数据（轮次、晋级、对手、成绩）。

### 运行与审计数据
**定位**：支撑可运维、可追溯。  
**核心内容**：
- 操作日志、异常日志。
- 导出记录（待补充是否单独留痕）。

**数据协同价值**：
- 用统一身份和组织主数据打通学习、考试、竞赛数据链。
- 用统一结果口径支撑分级监管与复盘分析。
- 为后续精细化运营（内容优化、激励策略）提供基础。

## 设计原则

- **分级治理优先**：任何功能设计先满足国家级与省市县级权限边界。
- **流程闭环优先**：设计必须覆盖“配置-执行-统计-复盘”完整链条。
- **移动端易用优先**：学员侧交互应低学习成本，关键操作路径短。
- **结果可追溯优先**：关键操作、关键结果必须可查可导可审计。
- **数据同源优先**：同一指标在不同页面口径保持一致。
- **兼容统一登录**：围绕外部身份体系设计用户映射与会话机制。

## 功能规划原则

### 优先级判断标准

1. **政策与赛务刚需** > **分级治理刚需** > **数据监管刚需** > **体验优化**
2. **必须实现（基础能力）**
   - 统一身份接入与用户映射
   - 题库/考试/竞赛主流程
   - 分级权限与组织管理
3. **优先实现（监管能力）**
   - 结果统计口径统一
   - 多维筛选与导出
   - 操作与异常日志完善
4. **重点打磨（学习成效）**
   - 学习路径可视化
   - 证书/勋章激励闭环
   - 内容推荐与搜索体验（待补充）
5. **适度投入（增值体验）**
   - 商城激励精细化运营
   - 服务中心智能化（待补充）

### 功能投入策略

- **赛训主链路（学习/练习/考试/竞赛）**：持续高优先级投入，保障稳定与口径一致。
- **分级治理与审计能力**：作为平台级能力持续补强。
- **激励与服务体验**：在主链路稳定后逐步优化。
